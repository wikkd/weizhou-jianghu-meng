守则一：遵循鸿蒙 UI 设计，使用鸿蒙开放的 UI 库

1.1 设计基准

  • 全站以 HarmonyOS 设计语言为唯一视觉基准：鸿蒙蓝 #0A59F7 主色、浅灰底 + 白卡片、胶囊按钮/分段器、大标题层次、底部半模态 sheet。
  • 所有页面必须引入 assets/theme.css，通过 CSS 变量取色，禁止硬编码颜色（内联 SVG 图标内部除外）：
令牌用途
--bg / --card页面底色 / 卡片底色
--ink / --muted主文字 / 次级文字
--line分隔线、描边
--brand / --brand-soft主色 / 主色浅底
--accent / --gold / --redlink强调色 / 金色（诗词）/ 红链
  • 明暗双主题必须同时支持：:root 与 [data-theme=dark] 双套变量已内置于 theme.css，新页面接入 THEME_INIT 初始化脚本（见 build_wiki.py 中的 page_html() 参考），默认跟随系统 prefers-color-scheme，手动切换用 localStorage 记忆。
  • 字体：UI 用 HarmonyOS Sans SC（内嵌方案见 UI_SPEC.md），诗词正文保留衬线字体。

1.2 图标库使用规范

  • 官方图标来源：D:/harmony资源包/HarmonyOS_Icons.zip（HarmonyOS 官方图标库，676 个 SVG，扁平结构，约 1.9MB）。
  • 入库方式：按需取用，禁止整包提交。流程：
  1. 从 zip 中选定所需 SVG（只读解压到临时目录挑选）；
  2. 复制到 assets/icons/ 目录；
  3. 命名规范化后提交。
  • 命名规范化（zip 内存在少量不合规范文件，入库前必须处理）：
  • 保留官方前缀语义：ic_public_*（通用）、ic_device_*（设备）、ic_contact_*（联系人）；
  • 文件名全小写下划线，去除空格（如 ic_Edit Group_filled.svg → ic_public_edit_group_filled.svg）；
  • UUID 命名的文件禁止直接入库，须先在官方库中确认语义并重命名，无法确认语义的不得使用。
  • 引用方式：
  • 首选：SVG 内容内联进 HTML（便于跟随主题变量换色，fill="currentColor"）；
  • 次选：<img src="assets/icons/xxx.svg"> 本地引用；
  • 禁止外链 CDN 或第三方图标源——全站保持零外部依赖。
  • 图标默认尺寸 24×24 视口，导航/按钮内 20×20，与文字间距 8px（gap: 8px）。
  • 新增图标须在本次改动中实际被引用，不许预囤未用图标。

1.3 动效细则（MOTION_SPEC.md）

  • 所有交互动效一律引用 assets/theme.css 的 --ease-*（非线性曲线）与 --dur-*（时长）令牌，禁止自造 bezier、禁止 transition: all；
  • 选型按 MOTION_SPEC.md §4 映射表执行；红线与验收清单见其 §5/§6。

守则二：所有构建的页面都要有明确的上下交互逻辑

2.1 页面上下文完整性（每个页面必须四件套齐备）

要素要求
来路页面头部导航含「返回/上级」路径，用户能回到上一级（如词条页 → 总目录 → 主页）
去路页内 [[词条链]]、入口卡片指向明确，红链必须落到占位页（wiki/待创建.html）而非 404
状态反馈加载/过滤/搜索空结果/主题切换等操作均有可见反馈；搜索无结果时显示提示文案与建议动作
逃生口任何深层页面 2 次点击内可达主页导航；页脚固定站点级链接（总目录 / 诗图 / KB / 修订历史）

2.2 交互逻辑编写要求

  • 新页面/新交互先在构建脚本中写清交互说明（page_html() 模板参数或脚本头部注释），再写实现。
  • 所有客户端交互（搜索、过滤、主题切换、图集翻页）必须：
  • 无外部 JS 依赖，纯原生实现；
  • 失败降级可用——JS 禁用时内容仍完整可读（渐进增强）；
  • 键盘可达（Tab 焦点顺序、Enter 触发）。
  • 状态持久化：用户主动选择的状态（主题、筛选项）用 localStorage 记忆，键名统一前缀 wzjm_（如 wzjm_theme）。
  • 构建期校验：build_wiki.py 等构建脚本必须对死链（无落点的链接）输出警告清单，红链必须落占位页；构建输出中出现意外死链视为构建失败。

2.3 验收清单（每页过一遍）

  • [ ] 导航栏四入口 + 主题切换可用
  • [ ] 返回路径完整，无断头页
  • [ ] 链接无 404（红链落占位页）
  • [ ] 搜索/过滤有空态提示
  • [ ] 明暗两主题下文字对比度均可读
  • [ ] 移动端（<760px）布局不塌陷（侧栏折叠、卡片单列）

守则三：使用本地 AI 生图生成配图

3.1 生成方式

  • 配图一律用本地 AI 生图通道（WorkBuddy 内置生图工具，qwen-image 模型），不使用外部在线生图服务、不引用外部图片 URL。
  • 单张顺序生成：逐张调用，确认成功后再生成下一张，防止并发导致连接中断/结果丢失。

3.2 产出与归档

用途输出路径命名
诗词配图poems/沿用现有 poemXX 序列规则
词条头图/插图wiki/assets/ 或 assets/img/wiki-<ns>-<词条名拼音或编号>.png
页面装饰/横幅assets/img/banner-<页面名>.png
  • 生成后先本地核验（尺寸、内容、风格是否匹配诗词/词条语境），不合格即重生成，不得直接落库。
  • 图片入库前压缩到合理体积（单张建议 ≤ 500KB），保持零外部依赖。
  • 配图风格与鸿蒙 UI 协调：浅色底、留白充分、避免与主题色冲突的高饱和背景。

3.3 记录要求

  • 每批配图在当日记忆日志中记录：生成参数/提示词要点、产出路径、采用/废弃数量，保证可追溯、可复现。
