1. 使命与范围

把《苇舟江湖梦》及其衍生物料建成一套可持续演进的数字知识工程：线上站点（门户/知识库/诗图）、只读 Wiki 百科、量化分析产线。边界：不做在线编辑（P4 前不做）、不做伤害著作权的功能。

2. 角色与分工

角色职责
作者（霜月仲明）需求拍板、内容终审、红线确认、验收
AI 主控（WorkBuddy）规划、实施、构建、部署、线上核验、日志沉淀
并行 subagent批量生成 / 校对 / 扫描类任务，结果必须经主控核验
未来协作者fork + PR，合并权在作者

3. 仓库双域模型

  • 仓库根 = 网站工程：页面（index/kb/poems/wiki）、数据（knowledge_base.json 等）、构建（build_*.py）、运维（deploy.sh）。
  • 文学/ = 文学域：源文件、文本数据、分析脚本、skills、报告产物。内部同级结构不可拆（46 个脚本按 ROOT=脚本上级目录 取数）。
  • 分支：master 唯一开发分支；gh-pages 只归 deploy.sh 写入（确定性重建 + force-with-lease），禁止手改 gh-pages。
  • 产物红线：文学/产物/ 被 .gitignore 屏蔽，只经 _agentkit_stage/ 挂载到 gh-pages；该目录与原 zip 为部署/数据保底，不可删除。

4. 开发流程（八步）

① 需求/想法（作者拍板或 AI 提案）→ ② 规格落库（SPEC 文档 + commit，重大决策必须先写规格再动工）→ ③ 双域实施 → ④ 构建与门禁（DoD 不通过返工）→ ⑤ 提交推送（改完即 commit + push master）→ ⑥ bash deploy.sh 上线 → ⑦ 线上核验 → ⑧ 日志复盘（工作日志 + 教训沉淀）。

5. 验收门禁（DoD，七项）

  1. 构建全绿：build_kb.py / build_wiki.py / build_home.py / build_html.py 零报错
  2. 死链无新增：build_wiki 红链清单不扩大（有意红链需注明）
  3. 数据同源未破坏：wiki 信息框统计与 knowledge_base.json 一致，正文手写不与统计混写
  4. 页面类改动：双主题目检 + 375px 宽不横向滚动
  5. 站点运行时零依赖零外链（构建期除外）
  6. 推送完成 + deploy.sh 执行 + 线上抽查通过
  7. 工作日志已更新（当日 memory + 长期约定入 MEMORY.md）

6. 内容工作流（Wiki 词条）

  • 生命周期：content/<ns>/<title>.md 新建/修改 → python build_wiki.py → 门禁 → bash deploy.sh。
  • 命名空间白名单：人物 / 章节 / 地点 / 组织 / 术语 / 诗词；章节词条 title 不带顿号（「一」），顿号形式做别名。
  • 统计数字一律构建期回填（单源原则），手写只写叙事与描述性属性。
  • 别名自动生成重定向页；红链是显式信号，不是错误。

7. 技术约束

  • 运行时零依赖、零外链、单文件内联优先；构建脚本纯 Python 标准库。
  • 新增构建脚本必须幂等（可重复运行全量重建）。
  • 数据结构版本化：产物内嵌 schema_version，升级走迁移脚本。
  • 中文路径为项目常态（URL 会百分号编码，属预期）。
  • AI 改动文件前先 Read；大改动前先列出待操作清单。

8. 安全红线

  • 破坏性操作（删除/清空/重写/批量移动）必须先列清单、等作者确认。
  • 原始 zip 与源 docx 只读；解压输出到新目录；中文名按编码试探还原。
  • 外部公开动作（上线新公开内容）需作者知情。
  • 发版动作（版本号、CHANGELOG）先拍板；跨域推送前说明影响。

10. 路线图治理

  • P1 Wiki 骨架 ✅（2026-09-27）→ P2 全量词条+分类+搜索 → P3 鸿蒙双主题全站统一 → P4 编辑能力（CMS/评论）。

  • 计划外需求走流程 ①-② 重新立项，不夹带。

11. 沟通约定

  • 作者可用简短指令（"继续"/"开始"）驱动，AI 按最近一期计划顺序推进。
  • AI 结论必须给证据（构建输出/线上核验/代码级引用），可疑结论接受复核要求。
  • 教训与坑必须在当期日志沉淀，可复现流程优先固化为脚本或文档。
