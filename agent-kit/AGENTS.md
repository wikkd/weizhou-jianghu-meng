## 1. 项目是什么

《苇舟江湖梦》（作者：霜月仲明，60 章 / 约 23 万字）的**文本量化分析工程**：把小说原稿切分、人工标注、量化统计、可视化，最终沉淀为 HTML 报告体系 + SQLite 归档库。

- 这是**作者本人的作品分析项目**，非第三方版权内容，可放心处理。
- 全部流水线脚本用 `__file__` 推导项目根目录，**在任何工作目录下运行均可**，无需 `cd`。

## 2. 快速启动（接管前 5 分钟）


## 5. 流水线总览（详见 README 全表）

- **01–02** 分章 + 标注聚合
- **03–07** 五大量化模块（统计推断 / 风格 / 词汇 / 情感 / 人物网络）
- **08–16** 各维度 HTML 报告 + 数据归档（13）
- **17–22** 量化扩展（角色性格 / 口头禅 / 对打动作 / 地理描述 + 审查）
- **23–25** 叙事可视化（四维流程图 / 扩展 / 深度）

依赖第三方库的只有 **03 (numpy/scipy)、05 (jieba)、06 (snownlp)、07 (networkx)**，其余仅标准库。

## 6. 项目铁律（务必遵守）

1. **标注文件只聚合、不重建**（见上）。
2. **报告图表优先内联 SVG**，禁止依赖外部 CDN（ECharts/Plotly 均不可靠，见 `WORKFLOW.md` §8 可视化规范）。产物根目录的 `echarts.min.js` / `mermaid.min.js` 是离线 bundle，仅 23–25 可视化页使用。
3. **SVG 文字用具体字体栈** `'PingFang SC','Microsoft YaHei','Noto Sans SC',system-ui,sans-serif`，禁止 CSS 变量；marker 用固定色 `fill="#RRGGBB"`。
4. **所有脚本用 `__file__` 定位根目录**——新增脚本必须遵守，禁止硬编码绝对路径。
5. **破坏性操作（删除/清理/重写/重组）前**，先列出文件清单 + 安全等级表，经用户确认后执行；删除一律走废纸篓。
6. **报告风格统一**由 `产物/theme.css` 驱动；新增报告引用它，不要自造视觉体系。报告分类目录见 `产物/00_总览导航`…`05_制度家族`。
7. **修改数据后重跑流水线**按编号顺序 01→26 执行（可跳过与改动无关的步骤），并同步更新 README 与记忆日志。

## 7. 已知风险与未决事项

- **第 60 章无人工标注**：`all_tags.json` 只覆盖 1–59 章，导致派生产物（人物网络出场章数、统计推断、章节结构、标签看板）不含第 60 章。**补第 60 章标注（接入 tags_batch 并跑 `02_aggregate_tags.py`）是最高优先待办**。
- **平均句长口径冲突**：风格计量（29.76）vs 词汇计量（25.74）口径不一致，需对齐。
- **角色提及数字差异**：分析报告与人物网络对角色提及数口径不同（08 vs 07），需核对。
- **性格量化置信度低**：角色性格六轴置信度（约 0.13）需人工校验。
- **统计推断 Bonferroni 后仅部分显著**：表述需谨慎（见 `数据/analysis/stats_inference.json`）。

## 8. 协作模式（本项目的工作方式）

- **驱动方式**：用户（霜月）用简短指令驱动多步任务（如"继续"），AI 逐项推进并主动汇报。
- **风格偏好**：结论先行、结构化输出（表格 / 分版本逐项拆解）；架构图偏好中文节点 + 科技蓝 + 流程/流转式叙事。
- **并行子代理**：批量量化 / 报告归纳时派多个 general-purpose subagent 并行（曾用 5 agent 并行量化、3 agent 并行归纳 28 份报告），主上下文汇总整合。
- **迭代纪律**：报告优化用"评估 → 改进 → 实测验证（无头 Chrome 截图）→ 保留/回滚"的棘轮流程（对应 `skills/01-darwin-skill`）。
- **记忆维护**：每完成实质性工作，追加一条到 `.workbuddy/memory/YYYY-MM-DD.md`；长期规范写入 `MEMORY.md`。
